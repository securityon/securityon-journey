첫 아키텍처 노트에서는 Windows 기본 연구환경 구축과 WSL2 사전 점검을 하나의 다음 단계로 생각했습니다. 실제 작업을 시작해 보니, 개발도구를 설치하기 전에 운영체제 자체의 출발점을 정리하는 데 별도의 기록이 필요했습니다.

기존 기업 마스터 이미지의 라이선스와 조직 등록 상태를 확인하고, 복구 파티션의 역할을 살펴보고, 설치 USB의 문제를 해결하는 과정까지 포함됐기 때문입니다. 이번 노트는 그 작업을 거쳐 **클린 Windows 11 Pro 기준 상태를 확보한 과정**을 다룹니다.

## 1. 기존 마스터 이미지를 유지하지 않은 이유

이번에 구축한 장비는 **Samsung Galaxy Book Ultra 6**입니다.

- Intel Core Ultra 7 356H
- RAM 32GB
- NVIDIA GeForce RTX 5060 Laptop GPU 8GB
- Samsung NVMe SSD 1TB

노트북은 제가 소속된 회사의 장비이지만, 실제로는 다른 회사에 상주하며 사용할 예정입니다. 장비를 제공한 회사와 실제 사용 장소의 보안 요구사항, 필수 보안 프로그램, 네트워크 정책이 서로 다릅니다.

이 조건에서는 기존 회사의 마스터 이미지를 그대로 보존하는 실익이 크지 않았습니다. 실제 사용 환경에 들어가기 전에 운영체제를 새로 설치하고 업데이트와 하드웨어 인식 상태를 확인한 뒤, 그 위에 필요한 구성을 쌓는 편이 이후 변경사항을 이해하기에도 낫다고 판단했습니다.

다만 바로 재설치하기보다는 현재 이미지에 무엇이 들어 있는지 먼저 확인했습니다.

## 2. 운영체제, 라이선스와 조직 등록 상태 확인

기존 설치 상태는 다음과 같았습니다.

| 항목                            | 확인한 상태                    |
| ------------------------------- | ------------------------------ |
| 운영체제                        | Windows 11 Enterprise          |
| 버전                            | 25H2                           |
| OS Build                        | 26200.8246                     |
| 이미지                          | 기존 회사의 기업 마스터 이미지 |
| 설치된 Enterprise 라이선스 유형 | Volume KMS Client / GVLK       |
| 펌웨어에 포함된 키              | Windows Professional OEM:DM    |

여기서 구분할 필요가 있었던 것은 **현재 설치된 Enterprise의 라이선스 유형과 장비 펌웨어의 Pro OEM 키가 서로 다르다**는 점입니다. 기존 Enterprise/KMS 구성을 유지하는 대신, 펌웨어에 `Windows Professional OEM:DM` 키가 존재하는 것을 확인한 뒤 Windows 11 Pro를 새 기준 운영체제로 선택했습니다.

조직 등록 관련 항목도 확인했습니다. `AzureAdJoined`, `EnterpriseJoined`, `DomainJoined`, `WorkplaceJoined`는 모두 `NO`였습니다. 이는 당시 확인한 등록 상태의 기록이며, 장비가 실제 사용 장소의 보안 요구사항까지 충족한다는 의미로 해석하지 않았습니다.

기존 마스터 이미지에서는 BitLocker도 활성화돼 있지 않았습니다. 이 역시 재설치 전 상태에 대한 기록으로 남겼습니다.

## 3. 기존 디스크와 복구 구성

기존 SSD에는 운영체제와 데이터 영역 외에도 여러 복구 파티션이 있었습니다.

| 파티션        | 기존 용량   |
| ------------- | ----------- |
| EFI           | 약 100MB    |
| MSR           | 16MB        |
| C:            | 약 521.57GB |
| Recovery      | 약 816MB    |
| D:            | 약 400.39GB |
| Recovery_Data | 약 30GB     |
| SAMSUNG_REC   | 약 1GB      |

기존 마스터 이미지에서는 `reagentc.exe`를 확인할 수 없었습니다. 따라서 기존 복구 파티션이 존재하더라도, 그 구성을 새 연구환경의 표준 Windows 복구 구조로 그대로 이어받는 것은 적절하지 않다고 판단했습니다.

Samsung 복구 파티션은 기존 OEM 환경에 속한 구성이었습니다. 앞으로 사용할 환경에서는 그 이미지로 돌아갈 필요가 없었으므로, 기존 복구 파티션을 보존하는 것을 새 설치의 전제로 삼지 않았습니다. 이후의 복구 방식은 새 기준 상태와 데이터 배치에 맞춰 따로 설계하기로 했습니다.

## 4. 새 Windows 설치의 기준

새 운영체제는 Windows 11 Pro로 정했습니다. 기존 기업 마스터 이미지에 개발도구를 추가하기보다, 클린 설치를 연구환경의 출발점으로 삼았습니다.

설치 언어와 지역 설정은 다음과 같이 선택했습니다.

| 설정                   | 선택                     |
| ---------------------- | ------------------------ |
| Windows 설치·표시 언어 | English (United Kingdom) |
| 지역·시간·통화         | Korea                    |
| 키보드                 | Korean Type 3            |
| OOBE 계정              | 개인 Microsoft 계정      |

Windows는 영국 영어 환경으로 사용하되, 지역 설정은 실제 사용하는 한국에 맞췄습니다. 한영 전환에는 Shift+Space를 선호하기 때문에 Korean Type 3 키보드를 선택했습니다.

이 단계에서는 연구·개발 스택을 추가하지 않고, 운영체제 설치와 기본 장치 상태 확인을 먼저 마무리하기로 했습니다.

## 5. 설치 USB에서 확인한 문제

설치 과정에서는 Wi-Fi를 바로 사용할 수 없어 처음부터 네트워크 연결이 가능한 상태는 아니었습니다. 별개로 첫 번째 설치 USB도 완전하게 만들어지지 않은 상태였기 때문에, 네트워크 지원과 설치 미디어의 완전성을 나눠서 확인할 필요가 있었습니다.

부팅 파일은 있었지만 실제 Windows 설치 이미지인 `install.wim`, `install.esd`, `install.swm` 중 어느 것도 없었습니다. 부팅 파일이 있다는 것만으로 설치 가능한 미디어가 준비됐다고 판단할 수 없었습니다.

두 번째로 만든 USB에는 분할 WIM 형식의 `install.swm` 파일들이 포함돼 있었습니다. **FAT32에는 단일 파일 크기 제한이 있어 설치 이미지를 분할 WIM으로 담을 수 있습니다.** 따라서 단일 `install.wim`이 없다는 이유로 다시 불완전한 미디어라고 판단하지 않았습니다. 이번에는 설치 이미지가 포함돼 있는지 확인한 뒤 사용했습니다.

검증한 두 번째 USB로 Windows 설치는 정상적으로 진행됐습니다. 이 과정에서 네트워크 지원과 설치 미디어의 실제 내용을 별개의 확인 항목으로 다뤄야 한다는 점을 기록해 두었습니다.

## 6. 업데이트와 장치 상태 확인

클린 설치 후 Windows Update를 완료했습니다. 장치 관리자에서는 알 수 없는 장치나 문제가 표시된 장치가 없었습니다.

Samsung, NVIDIA, Intel 관련 장치도 일반적인 업데이트 과정을 거쳐 정상적으로 인식되는 상태를 확인했습니다. 이 기록에서 중요한 결과는 최종 장치 상태가 정상이었다는 점입니다. 모든 제조사 구성요소의 설치 경로를 Windows Update 하나로 단정하지는 않았습니다.

이 시점의 확인 범위는 운영체제와 하드웨어 인식까지입니다. GPU가 인식됐다는 사실을 CUDA나 PyTorch 연구환경의 검증 결과로 보지는 않았습니다. 해당 스택은 아직 설치하지 않았습니다.

## 7. 달라진 구축 순서와 이번 단계의 완료 기준

첫 아키텍처 노트의 로드맵은 최초 설계 시점의 기록으로 그대로 남깁니다. 실제 구현에서는 그때 하나로 묶었던 **Windows 기본 연구환경 구축과 WSL2 사전 점검**을 더 작은 단계로 나누게 됐습니다.

먼저 클린 OS 기준 상태를 확보하고, 다음으로 저장공간과 일상 작업환경을 정리한 뒤, 연구·개발 스택과 WSL2 사전 점검으로 이어지는 순서입니다. 운영체제 교체만으로도 라이선스, 복구 구성, 설치 미디어와 장치 상태를 각각 확인해야 했기 때문에 별도 단계로 구분하는 편이 실제 작업을 더 정확하게 설명했습니다.

이번 단계에서 확보한 상태는 다음과 같습니다.

- 클린 Windows 11 Pro 설치
- Windows Update 완료
- 알 수 없는 장치나 문제 장치가 없는 하드웨어 인식 상태
- 연구·개발 스택 설치 전의 기준 상태
- 저장공간과 데이터 배치를 정리할 준비 완료

기존 마스터 이미지 위에서 무엇을 유지할지 고민하던 단계에서 벗어나, 이후의 모든 변경을 비교할 수 있는 명확한 Clean Windows Baseline을 확보했습니다. 다음 Storage & Productivity Baseline 노트에서는 이 기준 상태를 바탕으로 운영체제와 데이터를 분리하고, 매일 사용할 생산성 도구와 저장공간 구성을 정리합니다.
